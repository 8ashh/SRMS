# User Guide & Viva Defense Companion

**Academic Performance Analytics & Student Record Management System (SRMS)**  
**Madhav Institute of Technology & Science (MITS), Gwalior**

This guide provides step-by-step instructions for operating the system and explains the key Python files in plain language to assist college students during project demonstrations and viva examinations.

## Part 1: How Each Role Uses the Website

### A. Administrator Role
*Sign in using: `admin` / `admin123`*

1. **Executive Dashboard (`/admin/dashboard`):**
   - View top KPI cards (Total Students, Faculty, Subjects, Marks Count, Average Attendance, Students at Risk).
   - Inspect visual charts: Grade distribution, subject averages, pass/fail donut, and sequential test trends.
   - Review high-priority risk alerts and recent audit activities.
2. **Student Management (`/admin/students`):**
   - Click **Add Student** to enroll a student (auto-creates their login account).
   - Use search and dropdown filters (Semester 1–8, Section) to filter students.
   - Click **Profile** on any student row to view their complete academic dossier.
3. **Faculty Accounts (`/admin/faculty`):**
   - Create faculty accounts by entering full name, username, and initial password.
   - Remove faculty access when necessary.
4. **Subjects & Courses (`/admin/subjects`):**
   - Define academic courses with their course code (e.g., `CS201`) and subject name.
5. **Marks Ledger (`/admin/marks`):**
   - Select student, subject, and test number to log obtained marks and maximum marks.
   - Edit or delete marks with confirmation dialogs.
6. **Classroom Attendance (`/admin/attendance`):**
   - Select a course and date (future dates are automatically blocked).
   - Use radio buttons (P/A) or click **All Present** to batch mark attendance.
7. **Academic Analytics (`/admin/analytics`):**
   - Interactive analytics dashboard showing cohort averages, grade distributions, and statistical tables.
8. **Anomaly Alerts (`/admin/alerts`):**
   - Review students flagged by Z-score ($Z < -1.5$) or falling score drops ($\ge 15\%$).
9. **Grade Predictions (`/admin/predictions`):**
   - View estimated final semester grades generated by Scikit-Learn.
   - Click **Retrain / Configure Model** to switch between Linear Regression and Random Forest.
10. **Reports & Exports (`/admin/reports`):**
    - One-click downloads for Student PDF Dossiers, Class Performance Reports, and Risk Rosters.
11. **Audit Logs (`/admin/audit-logs`):**
    - Inspect immutable operational logs tracking all student additions, mark edits, and logins.

## Part 2: Plain Language Guide to Key Python Files

| File | What It Does (Viva Explanation) |
| :--- | :--- |
| **`app.py`** | The main starting point of the Flask application. It connects our database, registers all the web pages (routes), sets global college branding, and handles errors like 404 or 403. |
| **`models.py`** | Defines our 6 database tables using SQLAlchemy: `Student`, `Subject`, `Mark`, `Attendance`, `User`, and `AuditLog`. It enforces important rules such as non-negative marks, valid dates, and unique roll numbers. |
| **`config.py`** | Holds all system settings, secret keys, and academic thresholds (like $75\%$ attendance minimum, $40\%$ passing mark, and grade cutoffs). |
| **`routes/auth.py`** | Handles user login, logout, and session security. It includes the `@role_required` decorator that makes sure students can't access admin settings and admins can access everything. |
| **`services/student_service.py`** | Contains the business logic for adding, searching, filtering, and deleting student records safely. |
| **`services/marks_service.py`** | Handles entering marks, validating that scores don't exceed the maximum, and calculating percentages using Python: `(score / max_score) * 100`. |
| **`services/attendance_service.py`** | Records daily attendance and calculates cumulative attendance percentage: `(present / total) * 100`. |
| **`services/analytics_service.py`** | Uses Pandas and NumPy to calculate class averages, subject comparisons, grade counts (A, B, C, F), and pass/fail statistics from the database. |
| **`services/anomaly_service.py`** | The early-warning engine. It calculates Z-scores ($Z = \frac{X - \mu}{\sigma}$) to spot unusually low scores and checks if a student's marks dropped by $15\%$ or more compared to the previous test. |
| **`services/prediction_service.py`** | Uses Scikit-Learn (Linear Regression / Random Forest) to predict final grades based on mid-term marks and attendance, and measures accuracy using MAE and $R^2$. |
| **`services/report_service.py`** | Uses `fpdf2` and `csv` to generate formatted PDF dossiers and CSV data sheets with MITS Gwalior styling. |
| **`services/audit_service.py`** | Keeps an activity ledger of important changes (like adding students, modifying marks, or logins) for administrative transparency. |
| **`seed_data.py`** | Fills an empty database with realistic demonstration data: 1 admin, 2 faculty members, 24 students, 5 subjects, test marks, and attendance. |
| **`tests/`** | Contains 22 automated Pytest test cases to prove that login, permissions, calculations, validations, and predictions work correctly. |

## Part 3: Top Viva Questions & Recommended Answers

### Q1: Why did you choose SQLite instead of MySQL or MongoDB?
> **Answer:** "SQLite is a lightweight, serverless relational database built directly into Python. Because this is a college-level micro-project designed for demonstration, SQLite eliminates external database server setup, requires zero network configuration, and keeps our academic data portable in a single file while still supporting full SQL transactions, foreign keys, and indexes."

### Q2: How does your anomaly detection work?
> **Answer:** "We use two complementary methods in Python:
> 1. **Z-score Analysis:** We compute how many standard deviations a student's score is from their class average: $Z = \frac{\text{Score} - \text{Mean}}{\text{StdDev}}$. If $Z < -1.5$, it flags that the student is performing significantly below their cohort peers.
> 2. **Sequential Trend Drop:** We compare consecutive tests (e.g., Test 2 vs. Test 1). If a student drops by $15\%$ or more, the system generates an early-intervention alert."

### Q3: How is the Machine Learning grade prediction built?
> **Answer:** "We use Scikit-Learn's Linear Regression and Random Forest Regressors. The model takes continuous assessment mid-term marks and attendance percentage as input features to predict the final semester score, which is then mapped to a grade (A, B, C, F). We evaluate model accuracy using Mean Absolute Error (MAE) and the $R^2$ determination score."

### Q4: How is student privacy and data isolation maintained?
> **Answer:** "Role-based access control is enforced in Flask sessions. When a student logs in, their identity is bound to their unique `student_id`. If a student attempts to view another student's dashboard or download their PDF report, our route guards check `session['student_id'] == requested_id` and immediately return an HTTP 403 Forbidden error."
